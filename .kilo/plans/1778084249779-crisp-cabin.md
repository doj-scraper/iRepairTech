# Plan to Fix Order Status Bugs

## Overview
Fix two bugs related to order status handling in the ecommerce system:
1. Add 'expired' back to order_status enum (removed in migration 009), and update worker to use transition_order_state RPC.
2. Update refund handling to use transition_order_state RPC instead of direct UPDATE.

## Bug 1: Add 'expired' to order_status enum
- **Issue**: Migration 009 redefined order_status enum without 'expired', breaking checkout.session.expired handler.
- **Solution**:
  - Create new SQL migration (010) to alter order_status enum and add 'expired'.
  - Seed pending → expired transition in order_state_transitions.
  - Update worker/src/queue/pollQueue.ts: Replace direct UPDATE with transition_order_state RPC call for expired events.

## Bug 2: Route refund through transition_order_state RPC
- **Issue**: charge.refunded handler uses direct UPDATE, bypassing validation and history logging.
- **Solution**:
  - Update worker/src/queue/pollQueue.ts: Replace direct UPDATE with transition_order_state RPC call for refunded events.

## Implementation Steps
1. Create new migration file: supabase/migrations/20260506000010_add_expired_status.sql
   - ALTER TYPE order_status ADD VALUE 'expired';
   - INSERT INTO order_state_transitions (from_state, to_state) VALUES ('pending', 'expired');

2. Update worker/src/queue/pollQueue.ts
   - For checkout.session.expired:
     - Query order id by stripe_session_id.
     - Call supabase.rpc('transition_order_state', { p_order_id: orderId, p_next_state: 'expired' })
   - For charge.refunded:
     - Use orderId from metadata.
     - Call supabase.rpc('transition_order_state', { p_order_id: orderId, p_next_state: 'refunded' })

3. Test the changes: Run lint/typecheck, and verify transitions work.</content>
