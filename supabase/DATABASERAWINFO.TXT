RLS policies (public schema)
RLS policies exist for these public tables (and actions):

public.inventory_parts: SELECT for public, and SELECT for authenticated
public.repair_services: SELECT for public, and SELECT for authenticated
public.profiles:
SELECT for public policy (definition shown as auth.uid() = id)
UPDATE for authenticated (id = auth.uid() and check id = auth.uid())
public.orders:
SELECT for public (auth.uid() = user_id)
INSERT / UPDATE / DELETE / SELECT policies for authenticated scoped by user_id = auth.uid()
public.order_items_parts: SELECT for public via order_id IN (select orders...); SELECT for authenticated via EXISTS with orders.user_id = auth.uid()
public.order_items_services: same pattern as parts
public.stripe_events: policy for service_role with ALL (write-side webhook/events)
(Also: is_active = true appears for the policy definitions returned.)

---## `public` FK graph (relationship map)

### Core relationships

- `public.profiles.id` → `auth.users.id`  
    (via `profiles_id_fkey`)
    
- `public.orders.user_id` → `public.profiles.id`  
    (via `orders_user_id_fkey`)
    

### Order line items → parent order

- `public.order_items_parts.order_id` → `public.orders.id`  
    (via `order_items_parts_order_id_fkey`)
    
- `public.order_items_services.order_id` → `public.orders.id`  
    (via `order_items_services_order_id_fkey`)
    

### Order line items → referenced catalog items

- `public.order_items_parts.part_id` → `public.inventory_parts.id`  
    (via `order_items_parts_part_id_fkey`)
    
- `public.order_items_services.service_id` → `public.repair_services.id`  
    (via `order_items_services_service_id_fkey`)
    

### Order state history

- `public.order_state_history.order_id` → `public.orders.id`  
    (via `order_state_history_order_id_fkey`)

### No FK links

- `public.inventory_parts` and `public.repair_services` don’t have FKs pointing outward (they’re referenced by order item tables).
- `public.order_items_parts` / `public.order_items_services` don’t reference each other (each is separate).
- `public.order_state_transitions` has a composite PK but no FK constraints (it’s a transition matrix).
